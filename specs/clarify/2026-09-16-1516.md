# Clarify Session 2026-09-16 15:16

## Idea

第一個功能需求:
我想要讓 HikePilot 這個產品能夠根據以下條件，推薦使用者(TA 是登山新手) 1~3 條適合且安全的登山路線:
1. 使用者的性別、年齡、體能、經驗、喜好
2. 使用者對登山路線的風險承受度(山況、天氣、難度)
3. 登山路線的即時資訊、當日天氣狀況

第二個功能需求:
當 HikePilot 推薦路線後，使用者決策路線後，生成對應的登山規劃書，內容包含:
1. 路線摘要
2. 分段行程
3. 天氣路況
4. 風險應對
5. 裝備補給
6. 交通資訊
7. 緊急應變(提供撤退條件、替代方案)
8. 行前 Checklist

## Flow Alignment 補充（使用者於對話中提供）

- 個人條件在註冊的時候（尚未使用前）需要填寫，使用完推薦路線後或爬完山的各項數據可回饋給推薦機制做下一次判斷（地圖疊圖、GPS追蹤定位、Apple Health整合、登山後回饋機制 — 使用者決定另立需求群組，不納入本次範圍）
- 零推薦結果時就寫「無符合資料」
- 路線即時資訊、天氣資料來源請 AI 協助尋找政府公開資料 API 或開源資料庫
- 規劃書使用可下載的 PDF 呈現
- 可要求重新推薦
- 註冊和登入直接串接 Google 登入
- 首次登入需要填寫個人條件，以問卷調查形式呈現（共 11 題，完整題項與選項見對話記錄），任一題可選擇不回答，每次重新推薦前都可選擇是否更新此問卷答案
- 可以導入 LLM model 搭配 RAG；規劃書就是依據個人條件、推薦結果、公開資料等生成
- LLM 為本次必須實作的推薦邏輯，採用 RAG（路線資料納入知識庫，LLM 從中檢索+排序），而非 LLM 自行搜尋
- Google OAuth 可以開另一個 client 專案

## Q&A

- Q: 問卷是否為請求路線推薦的強制前提？若使用者所有題目皆選擇不回答，系統能否仍以預設/中性條件推薦？ → A: 選項 B——必答題為「最近一年登山頻率」「曾完成且接近能力上限的代表路線」「可以舒適完成的單日行程」「曾實際完成或能獨立操作的登山經驗」「對不同登山情境的接受程度」「需特別考量的身體狀況」（即 Q1、Q2、Q3、Q4、Q5、Q11），其餘題目（Q6-Q10）維持可選擇不回答。
- Q: Google 登入是否同時處理「註冊」與「登入」（同一 Feature/Endpoint，帳號不存在則建立、存在則登入）？ → A: 選項 A——單一 Feature，以 Rule 區分「首次登入建立帳號」與「非首次登入」。
