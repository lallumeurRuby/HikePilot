# 澄清紀錄 — questionnaire-options Phase 01

## 背景

需求：為個人條件問卷 Q1-Q11 每題加入具體選項（代碼+文字），取代純文字輸入框。

## 問題與決議

### GAP-1: Q5「對下列登山情境的接受程度」缺少「情境」清單（矩陣的列）

使用者只提供了「接受程度」量表（矩陣的欄），未提供情境項目本身。

**決議**：採用以下 5 個情境作為 Q5 矩陣的列：

| 代碼 | 情境 |
|------|------|
| `steepness` | 陡峭上坡／下坡 |
| `scrambling` | 手腳並用攀爬 |
| `exposure` | 暴露感強的稜線／高落差地形 |
| `altitude` | 高海拔環境 |
| `navigation_difficulty` | 路徑不明顯／需要自行導航 |

### GAP-2: Q2「路線名稱＋體感」複合答案的儲存方式

原提案：沿用既有 `QuestionnaireAnswer(question_code, answer_value)` 單一字串欄位，編碼成 `"路線名稱｜體感代碼"`。

**決議**：不接受單一字串編碼。改為新增獨立題號 `Q2B`（體感，single_choice，必答），`Q2` 收斂為純「路線名稱」（open_text，必答）。兩者各自是一筆獨立的 `questionnaire_answer` 記錄。

## 影響

- `specs/features/profile/填寫個人條件問卷.feature`、`specs/features/recommendation/請求路線推薦.feature`：Background 新增「選項」欄、Q2 拆分為 Q2/Q2B、所有 Example 的 answer_value 改為選項代碼格式。
- 已同步至 `backend/tests/features/profile/填寫個人條件問卷.feature`、`backend/tests/features/recommendation/請求路線推薦.feature`。
- `specs/erm.dbml` 的 `route.terrain_*` 欄位與 Q5 情境代碼的對齊，留待 Phase 02（Entity Modeling）處理。
