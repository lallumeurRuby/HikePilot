# 系統抽象

## 實體清單

| 實體 | 性質 | 攜帶狀態摘要 | 對應 features subfolder |
|------|------|-------------|------------------------|
| User | Aggregate | google_id, email, name | features/auth/, features/profile/ |
| QuestionnaireAnswer | Aggregate（隸屬 User） | user_id, question_id, answer_value | features/profile/ |
| Route | Gateway（外部資料源同步的唯讀知識庫，非本次操作建立） | id, name, terrain_*, open_status | features/recommendation/ |
| Recommendation | Aggregate | user_id, has_matches, routes[] | features/recommendation/ |
| HikingPlan | Aggregate | user_id, route_id, sections[] | features/plan/ |

## 操作全景

| 操作 | 所屬實體 | 行為分類 | 輸入參數 | 回傳型別 |
|------|---------|---------|---------|---------|
| Google 登入/註冊 | User | Creation | google_id, email, name（自 Google Token 取得） | User + 是否首次登入 |
| 填寫/更新個人條件問卷 | QuestionnaireAnswer | Mutation | user_id, answers[]（Q1-Q11、Q2B） | 操作結果（成功/失敗） |
| 請求路線推薦 | Recommendation | Creation | user_id（自登入狀態取得） | Recommendation（routes[] 0~3 筆） |
| 生成登山規劃書 | HikingPlan | Creation | user_id, route_id, recommendation_id | HikingPlan（8 區塊內容、pdf_url） |

## 系統前置狀態拆解

| 部件 | 資料型別 | 建置方式 | 內部子結構 | Given 句型 |
|------|---------|---------|-----------|-----------|
| User | Data Table | aggregate-given | 無 | `Given 系統中有以下使用者：` |
| QuestionnaireQuestion（seed 參考資料） | Data Table | aggregate-given | 無 | `Given 系統中有以下問卷題項：`（固定 seed，放於各 domain 的 Background） |
| QuestionnaireAnswer | Data Table | aggregate-given | 無 | `Given 使用者 "Alice" 已回答問卷：` |
| Route（知識庫條目） | Data Table | aggregate-given | 無 | `Given 系統中有以下路線：` |

## 行為分類與句型骨架

### Creation（Google 登入、請求路線推薦、生成登山規劃書）

**When 句型模板**：`When {operation}:`（接 Data Table 或無參數）
**Then 句型模板（成功）**：`Then 操作成功` + readmodel-then 補充資料驗證
**Then 句型模板（失敗）**：`Then 操作失敗，violation_type 為 "<violation>"`

### Mutation（填寫/更新個人條件問卷）

**When 句型模板**：`When 使用者 "Alice" 提交問卷回答：`（接 Data Table）
**Then 句型模板（成功）**：`Then 操作成功`
**Then 句型模板（失敗）**：`Then 操作失敗，violation_type 為 "<violation>"`

## 共用契約

### Postcondition 模式

所有 Command 操作皆遵循「操作成功」/「操作失敗，violation_type 為 "<violation>"」的通用結果驗證模式（`success-failure` handler）。需要回傳資料的操作（推薦結果、規劃書內容）另用 `readmodel-then` 驗證回傳欄位。

### Violation 模式

| violation_type | 觸發規則 |
|----------------|---------|
| UNAUTHENTICATED | 使用者未完成 Google 登入 |
| MISSING_REQUIRED_ANSWER | 問卷必答題（Q1、Q2、Q2B、Q3、Q4、Q5、Q11）未填寫 |
| PROFILE_INCOMPLETE | 請求推薦時問卷必答題尚未完成 |
| INVALID_OPTION_CODE | 選項型題目（single_choice/multi_choice/matrix_single_choice）送出非題目定義的選項代碼 |
| ROUTE_NOT_SELECTED | 生成規劃書時未指定路線 |
| ROUTE_NOT_IN_RECOMMENDATION | 生成規劃書時選定的路線不在使用者當次的推薦結果中（Stage 2 分析 plan domain 時，從既有 Rule「必須從推薦結果中選定」直接推導新增） |

> 「無符合條件路線」是正常業務結果（`has_matches = false`），不是錯誤，使用 `readmodel-then` 驗證，不使用 violation_type。

## 共用句型

> Stage 2.5：4 個 domain（auth / profile / recommendation / plan）句型分析完成後萃取，
> 以下句型在全部 4 個 domain 中文字完全相同。

| # | 類別 | 句型 | Handler | 參數槽 |
|---|------|------|---------|-------|
| G1 | Given | `系統中有以下使用者：`（Data Table） | aggregate-given | user_id, google_id, email, name |
| T1 | Then | `操作成功` / `操作失敗，violation_type 為 "<violation>"` | success-failure | violation |

各 domain 句型.md 中的 G1 / T1 皆引用此處，不重複定義。

## 變異點索引

| 實體 | 特有行為 | 需要的專屬句型類別 |
|------|---------|------------------|
| User | 首次登入建立帳號 vs 非首次登入 | Given 區分使用者是否已存在 |
| QuestionnaireAnswer | 必答（Q1/Q2/Q2B/Q3/Q4/Q5/Q11）vs 選填（Q6-Q10）題的差異驗證；選項型題目答案需為合法選項代碼 | When Data Table 含缺漏必答題情境；含非法選項代碼情境 |
| Recommendation | 「無符合資料」為正常結果而非錯誤 | readmodel-then 驗證 has_matches=false，而非 violation |
| HikingPlan | 8 大區塊為固定結構輸出 | readmodel-then 驗證區塊清單 |
